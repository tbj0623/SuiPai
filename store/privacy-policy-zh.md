## 一、结论（先看这一段）

**随拍不收集、不使用、不共享、不转让任何个人数据。**

- 应用**没有账号体系**，没有服务器端，不含任何统计、广告或崩溃回传代码。
- 安装后**不需要联网即可使用全部功能**。
- 照片只读取你自己设备上的媒体库，编辑结果写回你自己设备上的 `Pictures/SuiPai`。
- 会出网的**只有两处**，且都需要你亲手发起：
  1. **互通** —— 同一 Wi-Fi 下把照片从一台设备直传到另一台，不经任何服务器；
  2. **智能配方**（可选，**默认关闭**）—— 只在你填入 API Key 并亲手按下按钮时，
     把**当前这一张照片的缩略图**发往**你自己选择的**那一家服务商。

除此之外，随拍不产生任何公网请求。

## 二、我们接触哪些内容，存在哪里

| 内容 | 存放位置 | 是否离开设备 |
| --- | --- | --- |
| 你的照片与视频帧 | 只读取你自己设备上的媒体库（MediaStore） | **否** |
| 编辑结果（成片 / 复制件 / 裁切 / 拼图 / 幻灯片导出） | 本机 `Pictures/SuiPai`，由系统媒体库管理 | **否** |
| 界面偏好（配方参数、排序、筛选条件、设备名、设置项） | 本机偏好文件 `suipai.xml` | 否（参与系统备份，见第五节） |
| 收藏与隐藏的照片 id 清单 | 本机偏好文件 `suipai.private.xml` | **否**（不参与备份） |
| 回收站账单（"我删掉了哪几张"） | 本机私有目录 `filesDir/trash.json` | **否**（不参与备份） |
| 搜索索引（文件名、日期、EXIF 摘要） | 本机私有目录 `filesDir/search_index.json` | **否**（不参与备份） |
| 收藏夹（用户自建相册） | 本机私有目录 `filesDir/collections.json` | **否**（不参与备份） |
| 你自己调好的自定义配方 | 本机私有目录 `filesDir/custom_looks.json` | **否**（不参与备份） |
| 搜索历史 | 本机私有目录 | 否 |
| 智能配方的 API Key | 先用 Android 密钥库中**不可导出**的主密钥加密，再写入 `suipai.ai` | **否**（不参与备份；明文不落盘，写入后界面不再显示） |

**没有账号，没有登录，没有服务器端**：随拍不收集你的内容，也无法远程删除或恢复任何内容。

## 三、权限与用途

每一条权限只服务于一个功能，没有备用权限，也没有后台采集。

| 权限 | 用途 | 何时申请 |
| --- | --- | --- |
| **相机**（`CAMERA`） | 取景与拍照。不在相册、一瞬或后台打开相机 | 只在进入拍摄界面时申请 |
| **读取照片**（Android 13+ 为 `READ_MEDIA_IMAGES`，并支持系统的「仅允许访问所选照片」模式） | 列出相册、编辑与批量整理 | 首次进入相册时 |
| **部分照片**（`READ_MEDIA_VISUAL_USER_SELECTED`，Android 14+） | 在系统「部分照片」模式下工作 —— 只授权部分时，随拍只看得到你选中的那些 | 同上 |
| **旧系统存储权限**（`READ_EXTERNAL_STORAGE` ≤ Android 12L；`WRITE_EXTERNAL_STORAGE` ≤ Android 9） | 仅为在旧版本上完成同样的读取与保存 | 同上 / 保存成片时 |
| **网络**（`INTERNET`、`ACCESS_NETWORK_STATE`） | 只服务两件事：「互通」在同一局域网内发现附近设备并传输图片；「智能配方」在你按下按钮时，把当前照片的缩略图发往**你在应用内挑定的那一家服务商**（可选服务商是应用内列出的几家官方接口，不是任意地址）。应用**不连接任何自有服务器** | 系统直接授予，不弹窗 |
| **设为壁纸**（`SET_WALLPAPER`） | 只对应查看器里的「设为壁纸」这一个动作 | 系统直接授予，不弹窗 |
| **震动**（`VIBRATE`） | 快门触感反馈。关掉「震动」开关之后不再触发 | 系统直接授予，不弹窗 |

**不请求**：位置、通讯录、通话记录、短信、麦克风、日历权限，也不在后台执行任何数据采集。

## 四、局域网互通（Sync）的数据边界

「互通」只在以下**全部成立**时才传输数据：

1. **你主动打开那一屏** —— 不进那一屏，不广播、不监听；
2. **两台设备在同一 Wi-Fi 局域网内** —— 关掉 Wi-Fi 就什么都传不了；
3. **两端都确认** —— 发送方选照片发起，接收方确认接收。

**传输内容**：照片字节本身，以及可选的「一瞬配方」参数（写进 EXIF，随照片走）。

**边界**：
- 传输是**点对点直连**（UDP 广播发现 + TCP 帧协议），**不经过任何中间服务器**；
- 不经开发者服务器，也不落地任何第三方；
- 接收方保存的文件落在**其本机**的 `Pictures/SuiPai`；
- 局域网内的设备名是你自己起的别名，只存在于本机与同网段广播里，不上传任何地方。

## 五、智能配方（可选，默认关闭）

这是一项可选的照片增强功能：让大模型看一眼照片，从应用自带的胶片配方库里推荐一条并说明理由。

- **默认关闭**。总开关处于关闭状态时，这个功能一次也不会出网；关掉开关后的行为与
  没有这个功能的版本一致（局域网「互通」是另一件事，不受这个开关影响）。
- **出网内容只有两样**：
  1. 当前这一张照片**长边 256 像素的缩略 JPEG**（JPEG 质量 85，平均约 11 KB）；
  2. 一段**固定的提问文字**。

  **原图、EXIF、拍摄位置、相册里的其它照片、你的文件名都不发送。**
- **发到哪里由你选**：应用内列出几家服务商的官方接口（默认智谱），你在「智能配方」里挑一家；
  **API Key 由你自己填写**，随拍不代你持有任何 Key，也不代你转发到别处。
  一旦发出，该照片缩略图的处理就受你所选服务商的条款约束。
- **只在按下按钮时发生**：没有后台上传、没有批量上传、不会在你不知情时重试。
- **返回的结果只是建议**：它只能选择应用配方库里已经存在的条目，
  应用不会因为它说了一句什么就改动你的原片。
- **随时可撤**：在「智能配方」里按「清除」即抹掉本机存放的加密 Key；
  关闭总开关即断掉这一项的全部公网请求。

## 六、系统备份与换机直传

| 文件 | 内容 | 参与云备份 / 换机直传 |
| --- | --- | --- |
| `suipai.xml` | 界面、相机、一瞬、相册与设置中心的偏好 | ✅ **是** |
| `suipai.private.xml` | 收藏与隐藏的照片 id 清单 | ❌ 显式排除 |
| `suipai.ai` | 加密后的 API Key | ❌ 不在规则里；且换机后主密钥消失，密文解不开 |
| `filesDir/custom_looks.json` | 你自己调好的自定义配方 | ❌ 显式排除 |
| `filesDir/` 下其余 JSON（回收站账单、搜索索引、收藏夹、搜索历史） | 见第二节 | ❌ 不在规则里 |

**系统自动备份只包含偏好文件 `suipai.xml`，不含任何照片。**
依据是 `app/src/main/res/xml/backup_rules.xml` 与
`app/src/main/res/xml/data_extraction_rules.xml`（云备份与换机直传两侧同口径，
两处都只写了一个 `<include path="suipai.xml"/>`）。

## 七、分享与第三方

应用内的「分享」调用**系统选择器**，由你选择的目标应用处理后续；
随拍不保留副本，也不记录你分享给了谁。

应用内不接入任何第三方 SDK。依赖只有 androidx、JetBrains Kotlin、Coil，均以
Apache License 2.0 提供，**不引入任何数据收集行为**。出网用的是 Android 自带的
HTTPS 连接（`HttpsURLConnection`），没有第三个网络库。

## 八、儿童与数据删除

随拍不面向 12 岁以下儿童，且**不收集任何用户数据**，因此不存在需要代为删除的记录。

如需清除应用产生的一切设置：
- **只清设置中心这一层**：应用内「设置 → 存储 → 清除设置」（只清 `cfg_` 开头的偏好，
  不碰照片、不碰收藏与隐藏清单）；
- **清全部**：系统「设置 → 应用 → 随拍 → 存储 → 清除数据」，或直接卸载。

**已保存的照片是相册中的普通文件**，请自行在系统相册或文件管理器中删除。
卸载随拍不会删除这些照片。

## 十一、如何把这份政策变成一个可访问的 URL

Play 要求**公开可访问的隐私政策 URL**。以下三种做法都能满足，按省事程度排序：

### 方案 A · GitHub Pages（推荐，免费且长期有效）

```bash
# 1. 新建一个公开仓库（名字随意，例如 suipai-privacy）
# 2. 把 store/privacy-policy.html 复制进去，改名为 index.html
# 3. 推到 main 分支
# 4. 仓库 Settings → Pages → Source 选 "Deploy from a branch" → main / (root)
# 5. 等一两分钟，得到：
#      https://<你的用户名>.github.io/suipai-privacy/
```

这个 URL 填进 Play Console 的「隐私政策」字段即可。HTML 版是自包含单文件
（CSS 内联、无外链），丢进去就能看。

### 方案 B · Gist raw（最快，适合先占位）

1. 打开 <https://gist.github.com>，新建一个公开 Gist；
2. 文件名填 `privacy-policy.html`，内容粘贴 `store/privacy-policy.html` 全文；
3. 创建后点「Raw」，地址形如：
   ```
   https://gist.githubusercontent.com/<用户名>/<gist-id>/raw/privacy-policy.html
   ```

⚠️ 注意：Gist raw 的 Content-Type 是 `text/plain`，浏览器会显示源码而不是渲染后的页面。
审核能读到内容，但体验不如 GitHub Pages。**建议只用它做临时验证，正式提交用方案 A。**

### 方案 C · 已有域名 / 静态托管

如果已经有站点（Vercel / Netlify / Cloudflare Pages / 自己的服务器），
把 `privacy-policy.html` 上传成 `/privacy` 即可。三家的拖拽部署都是一分钟内完事。

### 填表时的注意事项

- URL 必须是 **https**，且**不需要登录**就能访问（审核机器人不会登录）。
- 政策内容必须覆盖：**收集什么、怎么用、和谁共享、怎么删除、怎么联系**。
  本文与 HTML 版都已覆盖。
- 政策里的生效日期与适用版本要跟着发版更新（本文顶部那两行）。
- 改完政策后，Play Console 里的 URL 不需要变，但**下次提审时要确认内容仍然一致**。
