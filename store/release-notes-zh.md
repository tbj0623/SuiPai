## 一、这次最大的变化

### 1. 一整套视觉重做：暗房接触印样 v1

相片是相纸，界面是印样页的框线与编号。深灰绿的暗房底 `#101413`（不是纯黑）、
相纸白文字 `#EDEBE4`、琥珀 safelight `#E8A33D` 作为**唯一**强调色、近直角 2 dp 圆角、
所有编号走等宽字体。浅色「日光印样」主题不是简单反色，而是纸白那套独立配色
（同一支琥珀在纸白上只有 1.9:1，浅色主题用的是压深过的 `#855416`）。

真正解决的不是「不好看」，是**层级扁平**。规则只有一条：
**一屏只允许一个琥珀实心块**（主操作）。其余一切 —— 工具条格子、筛选芯片、次操作、导航 ——
都只有描边。于是「该按哪一颗」不需要读字。危险操作走定影红，且只出现在
删除 / 清空 / 覆盖 / 断开连接。

配套落地：完整字级系统（5 族 × 3 档，中文行高 1.45–1.6 倍）、间距阶梯（8 dp 基准）、
四档圆角（0 / 2 / 8 / pill，**没有 4/12/16**）、动效刻度（90/120/160/220/260/420 ms），
以及一组可复用组件（`PrimaryButton` / `PillChip` / `EmptyState` / `ValueWall`）与
Modifier（`paperEdge` / `greaseSelection` / `pressable` / `filmGrain`）。

### 2. 架构重构：加一屏不用再动 Activity

`MainActivity` 从 1172 行瘦到 **298 行**，只保留 7 件必须由 Activity 干的事
（生命周期 / `setContent` / 权限门 / 建 `AppState` / 两个 `ActivityResultLauncher` /
系统栏 / intent 收集）。

返回栈变成可保存、可单测的纯 Kotlin 实现：

```
AppRoute（目的地 + 字符串编码）→ BackStack（不可变、可编码）
      → NavPolicy（返回键优先级，纯函数）→ NavState（Saver）
      → AppNavHost / NavRender（这一帧该画哪一屏）/ AppChrome（底栏 + 页眉）
```

**行为零变化**是这次重构的硬指标：改前的每一条返回键优先级（批量中 → 清选择 → 退一层
→ 交系统）、每一条入栈去重规则（同 family 替换栈顶、Tab 不进栈）都原样搬过来，并由
`BackStackTest`（34 条）/ `AppRouteTest`（27 条）/ `NavPolicyTest`（15 条）/
`BatchMachineTest`（10 条）/ `NavRenderTest`（8 条）钉住。

路由总数从 7 条涨到 **27 条**（3 个 tab + 4 条原有覆盖层 + **20 条二级页**）。
这 20 条的来历可以逐条对上：`docs/arch/APP-ARCH.md` §11.1 那 14 条
（设置 / 外观 / 存储 / 关于 / 隐私 / 引导 / 回收站 / 收藏夹 / 收藏夹内页 / 搜索 / 回忆 /
回忆详情 / 拼图 / 幻灯片）+ §12.1 那 3 条（重复照片 / 存储分析 / 配方卡）
+ 导出与恢复 + 视频网格 / 视频播放 2 条。

而 `NavPolicy` 只多了一个字段 `hasLayer`：任何压在 tab 上的路由都自动获得返回键行为，
20 条新页一条都没有单独写返回逻辑。

### 3. 从「一个页面」变成「有层级的产品」

新增设置中心（8 组 + 搜索）、首启引导（3 屏）、隐私与数据中心、导出与恢复，
以及页眉「更多」抽屉（看照片 / 整理 / 设置三组共 11 个入口）。
每一屏都能用系统返回键逐级退出。

**原图始终保留，绝不上传。** 这一条没有变，也不会变 —— 它是这个应用存在的前提。

## 二、新增

### 设计系统 v1（`ui/design/`）

`SuiPaiTokens`（两套主题成对）/ `SuiPaiType`（字级）/ `Spacing` / `Motion` / `Surfaces` /
`Components`。四条守卫测试把它们钉住：对比度 ≥4.5:1、两套 token 键集合与顺序一致、
间距与圆角阶梯严格递增、字级矩阵每列严格递减。

### 设置中心（8 个分组）

通用 / 外观 / 相册 / 相机 / 一瞬 / 隐私 / 存储 / 关于，共 **37 项**。顶部带搜索，
输入「缓存」「画质」「隐私」「jpeg」「grid」都能直接跳到对应项。

- **外观**：主题（跟随系统 / 暗房 / 日光印样）、字号（小 85% / 标准 / 大 115% / 特大 130%，
  **叠加在系统字级之上**）、照片网格（密排 64dp / 小格 86 / 标准 118 / 大格 168）、
  缩略图质量（省电 256 px / 标准 420 / 清晰 720）、减弱动效。带一块**即时预览**，
  选了当场就能看到格子密度变成什么样。
- **存储**：本机数据 / 图片缓存 / 相册照片（**分三行写清，不相加**）、清除缓存、
  导出「本机数据说明」、清除设置（两步确认）。
- **关于**：整页，把原来的「关于随拍」抽屉升级上来（抽屉保留未删）。

每一行都是可点节点自带名字与当前值，读屏能听出「主题，暗房」。
**没接通读数的项会明说「等接线」并灰着**，不假装生效。

### 首启引导（3 屏）

① 把相册当成印样页翻 → ② 一瞬能做什么 → ③ 原图不出这台手机。
可左右滑、可跳过（第一屏就能跳），最后一屏的主按钮是「授权相册并开始」，接系统权限弹框。
引导里**不申请权限**（它只把「最后一步是哪一屏」报给调用方），权限由 `PermissionGate` 单独挡。

完成态是两个条件的与（`onboarded` + `contentVersion`），**幂等** —— 连读三次答案一致；
设置里的「重看首次引导」只退版本号、不清完成态，所以中途退出不会被永远当成新用户。

### 隐私与数据中心

- **数据去向逐条说明**：照片在系统媒体库、偏好在本机 `suipai.xml`、
  收藏与隐藏清单在 `suipai.private.xml`（不进备份）、Key 加密存放在 `suipai.ai`。
- **权限逐项用途**：7 行覆盖 manifest 里全部 9 条权限（合并显示 `INTERNET +
  ACCESS_NETWORK_STATE` 与 `READ_MEDIA_IMAGES + READ_MEDIA_VISUAL_USER_SELECTED`），
  每一条都写清「什么时候申请 / 只服务于哪一件事」。这张表与 `AndroidManifest.xml`
  由 `SettingsUiGuardTest` **双向**核对：manifest 有而页面没解释 → 红；页面解释了不存在的 → 红。
- **「导出本机数据说明」**：手写 JSON（不引序列化库），列出这台设备上随拍到底存了哪些偏好、
  值是什么，可一键复制给别人看。
- **「清除设置」**只清 `cfg_` 前缀，不碰照片、不碰收藏与隐藏清单，并在按钮上写明白。

### 导出与恢复（备份文件）

一个 UTF-8 的 `.json`，`schema = 1`，装 7 类东西：设置（只装真的落过盘的键）、
自定义配方（`SPLOOK1:` 文本，与「导入配方」同一个格式）、收藏夹、收藏 id、隐藏 id、
搜索历史。**照片本身不在里面。**

- 两种合并方式：`REPLACE`（以文件为准）/ `UNION`（两边合并）。
  界面上**默认一个都不选** —— 任何默认值都会变成「没读就下一步」的快捷方式。
- 读的时候有 **16 MB 上限**：选错文件可能是几百 MB 的视频，直接 `readBytes()` 会当场 OOM。
- 读到比当前大的 schema **整包拒绝**，不许「按旧语义尽量解」——那是静默改数据。
- 导出前有一块定影红的提醒：这个文件不含照片，但含**你收藏了什么、藏起来了什么、
  把哪些配方起了什么名字、最近搜过哪十个词**，请放在只有你能看到的位置。

### 回收站（30 天）

删除不再立刻销毁：照片先搬进 `Pictures/SuiPai/回收站`，账单记在 `filesDir/trash.json`。
30 天内随时可以恢复，第 30 天起可彻底删除，或由下次启动自动清理。

**角标与清理读的是同一个天数函数**，所以不会出现「角标说还剩 1 天、实际已经删了」。
账单是唯一真值：读不到 = 回收站是空的；**绝不**因为 json 坏了就去清目录 —— 那是真的丢照片。

### 收藏夹（用户自建相册）

除了系统相册目录，现在可以自己建册、把照片收进去。上限 200 个集合 / 每册 5000 张。
收藏（星标）与收藏夹是两件事：星标是「我喜欢」，收藏夹是「我按主题收好了」。
`photoIds` 是 `List` 不是 `Set`，因为**顺序是用户的**。

### 全库搜索

搜索不再只翻首屏已加载的那几百张：独立的索引器把**全库**扫成一份可落盘的 JSON
（只读文件头 64 KB 取 EXIF 摘要，**不解码原图**），查询在内存里对全库打分，
并给出**命中原因**（文件名 / 相册 / 日期 / 相机 / 镜头 / 类型）。

- **日期模式**：`2024`、`2024-09`、`9月21日`、`9月`、`今天` / `昨天` / `今年`。
  整串是日期时只当日期查 —— 否则搜「今天」会命中 `今天的云.jpg`。
- **中文按字切、字序必须一致**：按字才能覆盖词在中间的情况，保序才不会把「海上日出」
  也当成「上海」。
- **多词 AND**：`上海 外滩` 只留同时满足两段的；单段内部的英文词同样 AND。
- **命中原因角标**让「为什么它在结果里」看得见；它也是结果分组的键。
- 搜索历史最多 10 条、去重、按时间倒序，落 `filesDir/search_history.json`。
- 索引是**可重建的缓存**：删掉只会下次重扫；一张都没扫到时**保留旧索引**
  （媒体提供方抖一下、撤权限、部分授权都会走到这里）。

### 一瞬 · 专业版

在原有 7 条滑杆之外，补上专业分级能力：

- **曲线**：2–16 个控制点，Fritsch–Carlson 单调三次 Hermite 插值。
  选它而不是自然样条，是因为后者在陡峭段会过冲 —— 曲线是用户亲手拖的，
  过冲意味着「我没动那里，画面怎么亮了一块」。端点锁 x，中间点夹在邻点之间。
- **HSL 分色**：红 / 橙 / 黄 / 绿 / 青 / 蓝 / 紫 / 品红 8 个色带，每带色相 ±30°、
  饱和 ±100%、明度 ±25%。带间用 smoothstep 交叠，**权重和恒为 1** ——
  缺了这一条，「只把蓝色调亮」会顺手整体提亮。热循环查 `WEIGHT_LUT[360×8]`。
- **局部蒙版**：径向与线性两种，最多 4 个，可调羽化与强度。新建时默认带一个非中性的
  调整量（线性 −0.30 EV 压暗、径向 +0.30 EV 提亮）—— 否则新加一个蒙版画面毫无变化，
  用户只会以为按钮坏了。
- **自定义配方**：保存 / 重命名 / 删除 / 导出 `SPLOOK1:` 文本 / 导入。导入失败一定说人话，
  不猜、不崩。

**中性输入（零偏移 / 恒等曲线 / 零调整蒙版）走快路径**，输出与旧版逐字节相同 ——
升级不会把你之前的调色结果改掉。性能上，4096×3000（12.29 MPix）单线程从基线 1302 ms
到三者全开 2382 ms，8 线程行带折算约 **300 ms**。

### 相机 · 专业模式

五项手动控制（ISO / 快门 / EV / 白平衡 / 手动对焦）+ 一个可开关的亮度直方图：

- **ISO 22 档**（50–6400，1/3 档一节）、**快门 40 档**（1/4000 – 2 秒）、
  **EV ±3**（1/3 档，19 档下标）、**白平衡 9 档**（2800K–9000K）、
  **手动对焦**按屈光度档位（随设备截断）+ 一根连续滑杆。
- **每一项都先问设备要得到范围才点亮**。要不到就置灰并给一句人话
  （「这台设备的相机不提供手动参数」），**永不把越界值递进 CaptureRequest**。
- **关 PRO 时五项一起复位成自动，并清空 session 上的 CaptureRequest options** ——
  只把开关关掉而不清，用户以为回到自动，照片还是按 ISO 3200 曝光。
- **直方图**走独立的第三路 `ImageAnalysis`（640×480、采样步长 8、64 桶、只读 Y 平面）。
  三路流排不下时降级成两路，直方图格子置灰并说明原因，**拍照与预览完全不受影响**。

### 拼图（12 套模板）

2–9 张多选后进拼图。12 套模板：二联竖 / 二联横 / 三联竖 / 三联横 / 三联栏 /
2×2 / 四联行 / 左栏四联 / 顶栏四联 / 3×2 / 2×3 / 3×3。

- 参数：边框 0–24 dp、外边距 0–48 dp、圆角 0–24 dp、底色四色、画幅三档、
  导出长边 2048 或 4096 px。
- **长按一格拖到另一格可以换位**；换的是格位表，所以「屏幕上看到的就是导出的」。
- 照片比格子少时按循环补图（不留空洞），比格子多时那一套模板会灰掉而不是悄悄少几张。
- 内存预算：源图一张一张解、画完立刻回收。9 张 4000px 原图**从来不会同时展开**，
  2048 输出时峰值约 21 MB（若按「全都解出来再画」的老写法是 432 MB 起）。

### 胶片边框 + 漏光

四种装裱样式：`NONE` / `35mm`（上下片基 + 等距齿孔）/ `120`（四边深色宽边 + 转记线 +
四角刻线）/ `拍立得`（三边窄白卡 + 下边 2.9 倍宽白卡）。

漏光 4 角 × 5 档强度，衰减是 `(1 − d/r)²`，半径 0.62，拉满也只有 0.62 alpha ——
它只是「漏」，不是滤镜。**顺序是先漏光、后边框**：片基与卡面是不透明的实物，
漏光只漏在画面上，不会把白卡染成橙的。

**强度 0 时逐像素不变**，而且在实现层保证（`hasAdornments == false` 时连一次 `getPixels`
都不发生），对三种写法逐字节比对过。

### 回忆

按天 / 月自动聚合六种卡片：某年今天、一年前的今天、最近一周、这个月、去年夏天、
第一次拍的那天。纯函数实现（**注入时钟与时区**），所以闰年、闰日当天、同月同日合并
这些边界都有单测钉着。

`DATE_TAKEN <= 0` 的照片不参与任何卡片 —— 那不是「1970 年 1 月 1 日」，是「日期不可知」，
塞进「某年今天」就是造一条假回忆。

### 幻灯片

全屏播放，间隔 2 / 3 / 5 / 10 秒四档，可循环、可随机。点一下画面暂停 / 继续，
左右滑手动翻页，下滑退出，音量键也能翻。

**随机不重复的口径是洗牌袋**，不是「reroll 直到不同」—— 后者在三张以上时没有
「取尽一轮」的保证。用 24 个种子量过：reroll 那一版有若干种子在一轮内漏掉某张，洗牌袋 0 个。

### 重复照片合并

只有三条同时满足才判为重复：**文件大小逐字节相等** + **拍摄时间相差 ≤120 秒** +
**dHash 汉明距离 ≤6/64 位**。

合并 = 删照片，所以取的是保守取向：**误删是产品级事故，漏报只是工具没用**。
聚类用并查集而不是两两配对（否则同一批照片会出现在多个组里，用户点「删除其余」时会重复删）。

性能上只对**候选**解缩略图（先按文件大小分组，砍掉 90%+），不对全库每张解码 ——
这是把它从「十几秒」压到「一两秒」的唯一一处。保留建议三种规则（最高分辨率 / 最大文件 /
最早拍摄），三条都**确定**：同一组输入永远给同一个答案。

### 存储分析

三个问题三个答案：一共占多少 / 大的都是什么 / 哪些能放心删。
6 档尺寸堆叠条（按像素分档，不按字节 —— 「4000×3000 却只有 200KB」是聊天软件压过的）、
按来源分类、最大 20 个文件。

**这一屏没有删除按钮。** 只报告，交给用户去各自的界面确认。
文案分层也是刻意的：只有「随拍加工件」敢用「可以清理」的语气 —— 因为它确实能从原片重新生成。

### 视频（只播不编）

能播你自己相册里的视频、能分享出去、能把当前那一帧存成一张照片。除此之外什么都不做：
不剪辑、不转码、不加水印、不后台播放。

封面缓存两层（磁盘 48 MB + 内存 8 MB），路径里带**字节数**——某些同步工具会就地替换同一行
的内容，只按 id 命名会一直显示上一段视频的封面。首帧取 **1 秒**而不是 0 秒（0 秒在不少编码上是黑场）。

存下来的帧叫 `SuiPai_视频帧_<时间戳>.jpg`，两个下划线 ⇒ 落进「加工件」，不会混进「随拍原片」那一档。

> ⚠ 这一版 **manifest 里没有 `READ_MEDIA_VIDEO`**。Android 13 及以上只能读到自己写入的行，
> 界面会如实说「系统没放行视频」，而不是说「还没有视频」。

### 桌面小组件 + 快捷方式

- **小组件「最近的照片」**：2×2 / 4×2 两种布局，按宽度自动切换；30 分钟刷新一次
  （系统允许的最小值）。`exported="true"` 是 Android 12+ 的硬要求 —— 写 false 编译照样过、
  装上也照样过，只是组件永远不会收到更新，桌面上那块会一直停在初始布局。
- **三个桌面快捷方式**：拍（快门）/ 传（互通）/ 改（一瞬，指向最近一张）。
  选这三条的理由不是「能做」，而是它们各自代表一条主路径的入口。

### 相册主屏与多选

- **空态重做**：区分「还没照片」「没读到库」「筛选后没结果」三种情况，
  并点名是哪个筛选 / 隐藏类把照片藏起来了。
- **多选重做**：进度只在跑的时候显示，结论只在结束时出现；批量删除的授权链
  （系统删除确认框）逐张走完，并如实报「删了几张 / 几张没允许」。
- **删除接管回收站**：本 app 的照片先搬进回收站（30 天可恢复），搬不动才退回真删；
  外来照片仍走系统授权框。进度按**真实成功数**报，不按「试到第几张」。

## 三、改进

- **导航**：新加一个屏幕不再需要改 `MainActivity`。加一个 `AppRoute`、一个 `when` 分支、
  一条往返用例即可。
- **首页加载**：缩略图优先走系统已缓存的 MediaStore 缩略图，冷启动不再先白约 10 秒。
- **无障碍**：每一颗动作格子都是 48 dp 命中区（画出来的框仍是 38 dp），
  标签、按钮角色与「已选中」状态在同一个节点上；横屏与平板各自排一遍版，**不横向滚动**
  （滚出视野的 Compose 节点根本不在语义树里，读屏与自动化都够不着）。
- **性能**：行带切分的调色管线全程可并行，无邻域依赖；曲线与分色都预计算成查找表，
  热循环里只有数组读。分色从「每像素遍历 8 个带」改成按色相角预合成后省了约 830 ms，
  蒙版从「每像素一次 sealed 分派」改成每行一次分派后省了约 1600 ms。
- **字体与字级**：完整字级系统 + 等宽编号家族，中文行高按 1.45–1.6 倍排版。
- **错误提示**：所有「点了没反应」的出口（分享、打开、跳系统设置、写剪贴板）
  现在都会说话，不再静默失败。
- **搜索**：不再只搜已加载的 400 张；结果为空时会明说「这次只搜了已索引的 N 张」，
  不再让人以为库里真的没有。
- **相机**：参数下发失败时**就地降级**并说一句话，绝不留一颗亮着却没生效的格子。

## 五、已知问题

- **多数新功能待装机验证**：设置中心、首启引导、隐私中心、回收站、收藏夹、搜索、拼图、
  回忆、幻灯片、专业调色、专业相机、重复照片、存储分析、视频、导出与恢复、桌面小组件。
  代码与 JVM 单测都过了，但**没有在真机或模拟器上走完整条用户路径**。
  这一条会在 0.7.x 里逐条消掉，结果记进 `ANDROID-VERIFY.md`。
- **iOS 壳尚未编译验证**。`shared` 的 KMP 引擎与 SwiftUI 壳的边界至今没有编译证据
  （Kotlin/Native 的 iOS target 不能在 Windows 上构建）。首次上 Mac 需要预留微调时间。
- **没有 `READ_MEDIA_VIDEO`**：Android 13+ 的视频页只能读到随拍自己写入的行。
- **分屏与折叠屏换外屏未在真机上量过**：`configChanges` 已补齐全套声明
  （`orientation|screenSize|fontScale|density|smallestScreenSize|screenLayout|locale|layoutDirection|uiMode|keyboard|navigation`），
  但那只让系统不重建 Activity，不改变分屏带来的布局后果。
- **预测式返回没有接线**：全项目 0 处 `PredictiveBackHandler` / `OnBackInvokedCallback`。
- **edge-to-edge 只在相机 / 查看器 / 一瞬生效**：相册与列表那一套没有画到状态栏底下。
- **外来照片不能进回收站**：只有随拍自己写入 `Pictures/SuiPai` 的照片才搬得动。
  对相机 / 截图 / 微信的图片点删除时会明确提示「这张不是随拍拍的，删不了」，而不是静默。
- **回收站恢复后 `DATE_TAKEN` 是恢复时刻**，不是原始拍摄时间（调用方还没把原时间传进来）。
- **旧版（≤0.6.x）设置的搬迁只在设置中心一层完成**：相机 / 一瞬 / 相册的老键仍然优先读取，
  新键作为初值。要完全统一口径还差一轮接线。
- **配方卡与投屏有实现、无入口**（`RecipeCardScreen` / `CastIntent` 全仓无调用点）；
  收藏夹能建册、能看，「把选中加进已有夹」还没有 UI。
- **专业相机的基本盘是设备能力**：模拟器大概率一整排都置灰，需要在真机上验一次。
  峰值对焦、RAW/DNG、HDR 包围曝光、测光模式选择**明确没做**，不是漏了。
- **商店截图仍是 0.6.0 的模拟器合成场景**，上架前需整组重拍（见 `store/listing-zh.md` 第六节）。
